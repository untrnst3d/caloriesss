# Бесплатный хостинг NutriDay: Render Free + Neon Free

Это отдельная версия. Предыдущие архивы не изменены. Приложение ещё не опубликовано.

## Что сохранено

React-интерфейс, API, формулы, анкета, регистрация, вход, дневник, продукты, порции, активности и обработка фото сохранены. Локально без DATABASE_URL используется прежняя SQLite. С DATABASE_URL используется PostgreSQL: изменён слой хранения и обработка ошибки занятого логина. Аватарки хранятся в PostgreSQL как BYTEA, поэтому отдельное платное файловое хранилище не нужно.

## Что проверено и что ещё проверить

Прошла сборка React и локальные тесты SQLite: регистрация, повторный вход после нового процесса, HTTPS-cookie, запрет чужого Origin, фото, сохранение профиля, арифметика дневника, продукты, порции, активности, изоляция данных двух пользователей и проверки ввода. Фронтенд, формулы и обработка фото не менялись.

PostgreSQL и перенос старой базы ещё НЕ прошли интеграционную проверку: среда подготовки запрещает серверные сокеты. Docker и реальный Render тоже не запускались. Поэтому сначала выполните tests/postgres_check.py на отдельной тестовой базе Neon. Это обязательная проверка перед переносом реальных данных. Нельзя обещать отсутствие ошибок только по проверке SQLite.

## 1. Создайте тестовую базу Neon

1. Откройте https://neon.com/ и зарегистрируйтесь.
2. Выберите Free, создайте отдельный проект для проверки. Не подключайте платный тариф.
3. В Connect скопируйте PostgreSQL connection string. Для теста/переноса используйте прямое соединение (отключите Connection pooling), сохраните sslmode=require и другие параметры, которые предлагает Neon.
4. Строка содержит пароль: вводите её только в переменные среды/настройки сервиса, не отправляйте в чат, не сохраняйте в GitHub.

## 2. Проверка на Mac

В терминале из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
python -m pip install httpx
cd frontend
npm ci
npm run build
cd ..
```

Вставьте строку подключения в скрытый ввод (команда для zsh на Mac):

```zsh
read -s 'TEST_DATABASE_URL?Вставьте строку тестовой базы Neon: '
export TEST_DATABASE_URL
printf '\n'
python tests/postgres_check.py
unset TEST_DATABASE_URL
```

Тест создаёт случайные временные схемы в тестовой базе, проверяет сценарии приложения и перенос SQLite, затем удаляет только созданные им схемы. После прерывания теста временная схема может остаться; её можно удалить в тестовом проекте. Ожидаемый итог: PostgreSQL and migration checks passed. Если есть ошибка — не переносите реальные данные и не выкладывайте приложение; сохраните текст ошибки без паролей.

## 3. Реальная база и старые данные

Создайте ещё один пустой проект/базу Neon Free для приложения. Если старые аккаунты не нужны — переходите к шагу 4: при первом запуске создадутся таблицы и 18 встроенных продуктов.

Если старые аккаунты нужны:

1. Остановите старое приложение и сделайте копию SQLite. Используйте backend/backup_db.py в локальном режиме без DATABASE_URL. Оригинал сохраните отдельно.
2. У старой базы должна быть актуальная схема v0.0.5. Если есть legacy_profile, сначала назначьте владельца через claim_legacy.py в копии SQLite, а потом переносите её.
3. Введите строку подключения ПУСТОЙ реальной Neon-базы:

```zsh
read -s 'DATABASE_URL?Вставьте строку пустой базы Neon: '
export DATABASE_URL
printf '\n'
python backend/migrate_sqlite.py /полный/путь/к/копии.sqlite3
unset DATABASE_URL
```

Переносятся аккаунты с прежними хешами паролей, фото, профиль, продукты, порции, дневник, активности и служебная отметка миграции. Сессии и счётчики попыток входа не переносятся: потребуется войти заново. Перенос выполняется одной транзакцией, при ошибке откатывается. При уже существующих таблицах скрипт отказывается работать и ничего не перезаписывает. SQLite открывается только для чтения. Сначала выполните проверку на ТЕСТОВОЙ базе!

## 4. Render

1. После решения публиковать загрузите содержимое этой папки в корень caloriesss. Рядом должны быть Dockerfile, render.yaml, frontend/ и backend/. Не загружайте базы, .env, .venv и node_modules.
2. В https://render.com/ войдите через GitHub, предоставьте доступ к нужному репозиторию.
3. New → Blueprint → caloriesss. Конфигурация render.yaml выбирает plan: free. Постоянного диска и платной базы Render здесь нет.
4. В поле DATABASE_URL вставьте connection string реальной базы Neon. Оставьте TLS-параметры. Вводите в Render, не в исходный код.
5. Проверьте, что сервис имеет тариф Free и нет платных ресурсов; затем создайте его.
6. Render соберёт React и запустит Python. Его HTTPS-адрес автоматически разрешается для авторизации.
7. Откройте ссылку, зарегистрируйтесь, добавьте фото и запись. Перезапустите сервис через Manual Deploy и убедитесь, что аккаунт и записи сохранились.

Собственный домен не нужен. Ссылка Render открывается на iPhone в Safari; Mac может быть выключен.

## Защита от случайной потери данных

REQUIRE_DATABASE_URL=1 в Render запрещает запуск без внешней базы. Если Neon недоступен, запрос завершится ошибкой, но записи не начнут сохраняться в исчезающий локальный файл. Нельзя убирать эту настройку ради обхода ошибки подключения.

APP_ENV=production и COOKIE_SECURE=1 включают требования HTTPS. Для собственного домена задайте PUBLIC_URL=https://ваш-домен. .env.example — образец, автоматически не читается.

## Бесплатные ограничения (проверены 12.11.2026)

Render Free засыпает после 15 минут без посещений, первое открытие может занять около минуты. 750 часов на workspace в месяц, отдельные лимиты на трафик/сборки. При подключённой карте превышение некоторых квот может оплачиваться: контролируйте Billing и лимит расходов; для демонстрации не подключайте оплату автоматически. Сервис может попросить проверку аккаунта — возможность запуска зависит от его правил.

Neon Free: 1 ГБ на проект и 100 CU-часов вычислений в месяц на проект согласно текущим условиям. Аватарки тоже занимают место. Не переключайтесь на платные планы автоматически. При достижении лимитов доступность может быть ограничена; бесплатность не означает безлимитность.

Проверка /api/health не обращается к базе, чтобы проверки хостинга не мешали ей засыпать. Реальные API-запросы обращаются к Neon. Пауза/перезапуск Render не удаляет внешнюю базу; удаление проекта Neon удалит её. Делайте резервные копии.

Не создавайте Render Free PostgreSQL вместо Neon: у него срок 30 дней.

## Резервные копии

Для локального SQLite: backend/backup_db.py.
Для облачного PostgreSQL используйте pg_dump совместимой версии на своём компьютере. Задайте PGDATABASE безопасно строкой подключения и выполните `pg_dump --format=custom --no-owner --file=nutriday-backup.dump`. Пароль не указывайте прямо в команде. Храните копию приватно, отдельно от Neon и GitHub. Восстановление сначала проверяйте на отдельной пустой базе.

## Локальный запуск

Прежние команды для двух серверов по-прежнему работают без DATABASE_URL. docker compose up --build -d запускает локальную SQLite-версию на http://localhost:8000 с томом. Это локальный режим, не проверка PostgreSQL. Не выполняйте docker compose down -v, если хотите сохранить данные в томе.

Ограничение прежней версии: за прокси общий лимит входов по IP может затрагивать нескольких пользователей (30 попыток за 15 минут). Сброса пароля по email пока нет.
