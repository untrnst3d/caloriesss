# Отчёт по версии 0.0.3

Дата подготовки: 10.10.2026. Проект: Caloriesss / NutriDay.

## Цель этапа

Добавить к дневнику питания простой учёт физической активности. Пользователь выбирает дату, вводит название занятия и количество потраченных калорий. Например: «Прогулка» — 150 ккал.

## Что изменилось

В `app.py` добавлены таблица `activities`, модель `Activity` и три адреса API: получение записей за дату, добавление и удаление. Данные сохраняются обычными SQL-запросами через `sqlite3`. Если название пустое или калории не больше нуля, сервер отклоняет запись.

В `App.jsx` добавлены форма, список занятий и сумма калорий активности. После добавления или удаления список обновляется. При смене даты загружаются записи другого дня. Показатель «Еда минус активность» показывает разницу двух сумм; суточная норма пока не рассчитывается.

Сохранены функции второй версии: продукты, свои порции, дневник и подсчёт КБЖУ. Анкета, рецепты и регистрация не добавлялись.

## Распределение задач на 4 учебных дня

Это предложенный учебный график и зоны ответственности для разбора и самостоятельной работы. Он не подтверждает фактически отработанные дни или личное авторство подготовленного кода.

| День | Ульяна — бэкенд | Диана — фронтенд | Результат дня |
| --- | --- | --- | --- |
| 1 | Разобрать поля новой таблицы: дата, название, калории. Создание таблицы без удаления старых данных. | Продумать расположение формы в дневнике. | Структура данных и простая форма. |
| 2 | Добавление и получение активности через API, проверка вводимых данных. | Отправка формы на сервер и вывод списка. | Запись активности за выбранную дату. |
| 3 | Удаление записи и подсчёт суммы за день. | Кнопки удаления, вывод суммы и обновление списка при смене даты. | Полный цикл работы с активностью. |
| 4 | Проверка базы после перезапуска и совместимости со второй версией. | Проверка сообщений и сборки интерфейса. Совместное обновление README и отчёта. | Версия готова к локальной проверке. |

Если нужен пятый день, его можно выделить на самостоятельное тестирование на Mac и исправление найденных ошибок.

## Проверки подготовленной версии

- Добавление, чтение и удаление активности через API.
- Разделение записей по датам и правильная сумма калорий.
- Отклонение пустого названия, отрицательных калорий и неверной даты.
- Сохранение данных при повторном запуске Python.
- Сохранность продуктов, порций и дневника при обновлении базы второй версии.
- Сборка React.

## Как объяснить работу

React отправляет введённые данные на FastAPI. Сервер проверяет их и выполняет INSERT в таблицу activities. Для отображения записей используется SELECT с условием по дате, для удаления — DELETE по идентификатору. Новый класс Activity проверяет входные данные, а не заменяет SQL-запросы.

Подготовка исходников выполнена с помощью ИИ. Распределение выше показывает, какую часть каждой участнице нужно разобрать и проверить.
