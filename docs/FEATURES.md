# NutriDay — версия 0.0.5

В этой версии добавлена одна возможность: личный аккаунт с авторизацией.
Регистрация, вход, выход и сохранение входа после обновления страницы.
Анкета, дневник, активности, свои продукты и порции принадлежат конкретному
пользователю. Исходные 18 продуктов доступны всем. Расчёт цели остался из v4.

## Запуск на Mac

Нужны Python 3.12+ и Node.js 22.12+ (или 24). Распакуй архив и открой терминал
в папке проекта. Первый терминал — сервер:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Второй терминал, из корня проекта — интерфейс:

```bash
cd frontend
npm ci
npm run dev
```

Открой адрес, который покажет Vite, обычно http://localhost:5173.
Если порт занят, Vite выберет следующий. Для разработки разрешены порты
5173–5199. Не переключайся между localhost и 127.0.0.1: для браузера это разные
адреса, поэтому вход нужно выполнить отдельно.

Зарегистрируй логин (3–32 латинские буквы, цифры, подчёркивание) и пароль
(8–128 символов). Регистр логина не важен. После регистрации вход автоматический.
Вкладка «Профиль» открывает анкету. Кнопка «Выйти» завершает текущую сессию.
Вход действует до 7 дней. После 5 попыток входа/регистрации для одного логина
или 30 с одного IP за 15 минут нужно подождать; успешные попытки тоже учитываются.

## Как устроен код

- `Auth.jsx`: `checkSession` проверяет вход при открытии и возвращении во вкладку;
  `submit` отправляет регистрацию или вход; `logout` завершает сессию;
  `notifyTabs` сообщает другим вкладкам об изменении входа. `AuthGate` показывает
  либо форму входа, либо приложение. При смене аккаунта состояние приложения сбрасывается.
- `client.js`: `api` отправляет запросы, прикладывает защитный заголовок и обрабатывает
  ошибки. При истечении сессии возвращает пользователя к форме входа.
- `security.py`: `hash_password` создаёт хеш PBKDF2-SHA256 с солью и 600 000 итераций;
  `verify_password` проверяет пароль; `start_session` создаёт сессию;
  `current_user` определяет пользователя по cookie. `register`, `login`, `me`,
  `logout` обслуживают маршруты авторизации. `protect_requests` проверяет источник
  изменения данных, `check_rate_limit` ограничивает попытки входа.
- `database.py`: `connection` открывает соединение и транзакцию, `query` выполняет
  SQL с параметрами, `init_db` создаёт таблицы или обновляет структуру старой базы.
- `app.py`: обработчики профиля, дневника, продуктов, порций и активностей получают
  пользователя через `Depends(current_user)`. В SQL используется его `user_id`.
  При изменении или удалении проверяется владелец записи.
- `claim_legacy.py`: `claim` однократно привязывает старые данные v4 к выбранному
  аккаунту. Запускается владельцем базы локально, через терминал.
- `App.jsx`, `dailyGoal.js`, `style.css`: основное приложение, расчёт прогресса цели
  и оформление. `index.html` — точка входа; `vite.config.js` — прокси API;
  `package.json` и `requirements.txt` — зависимости; `package-lock.json` создан npm.

Сервер хранит данные в `nutriday.sqlite3`, который создаётся при первом запуске.
Пароль в открытом виде не сохраняется. В браузере хранится HttpOnly cookie,
а на сервере — хеш случайного токена сессии. В localStorage нет паролей и токенов.
Выход отзывает текущую сессию, другие устройства остаются авторизованы.

## Перенос своих данных из v4

Если прежние записи не нужны, просто запусти новую версию: база будет пустой.
Для переноса:

1. Останови старый сервер. Сделай резервную копию `nutriday.sqlite3` из v4.
2. Скопируй эту базу в папку backend перед первым запуском. Не перезаписывай уже
   используемую базу v5 — у неё могут быть свои аккаунты и записи.
3. Запусти v5 и зарегистрируй аккаунт владельца старых записей. Пока не заполняй анкету.
4. Останови сервер. В терминале с активной `.venv` выполни, подставив свой логин:

```bash
python claim_legacy.py moy_login
```

5. Снова запусти сервер и обнови страницу.

До переноса старые записи сохранены в базе, но скрыты от всех аккаунтов.
Новый зарегистрированный пользователь не становится их владельцем автоматически.
Перенос выполняется один раз; существующая анкета аккаунта не перезаписывается.

## Проверка

Проверены API: разделение данных двух аккаунтов, запрет доступа без входа,
запрет удаления чужих записей, пароли, отзыв/истечение сессии, проверка источника,
ограничение попыток и перенос старых записей. Проверка интерфейса охватывает
регистрацию, подтверждение пароля, ошибочный вход, выход, обновление страницы
и переключение аккаунтов. Сборка: `npm run build`.

Это локальная учебная версия. Восстановление пароля и подтверждение почты не
добавлены. Сама SQLite-база не зашифрована: файл и резервные копии нужно хранить
у владельца. Публикация в интернет не выполнялась; для неё отдельно нужны HTTPS,
`COOKIE_SECURE=1`, точный список адресов в `ALLOWED_ORIGINS` и настройка хостинга.

Справка по хешированию: https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html

## Возможности фотографии профиля

Убрано пояснение с названием формулы под результатом расчёта. Сам расчёт сохранён.
Во вкладке «Профиль» добавлены загрузка, замена и удаление фотографии. Фото хранится
в SQLite отдельно для каждого аккаунта, сохраняется после выхода и повторного входа.
Сервер проверяет изображение, учитывает его ориентацию и создаёт квадрат 512×512.

Для перехода на раздельные папки следуй инструкции в корневом README.md.

`ProfilePhoto.jsx` отвечает за выбор файла и сообщения; `account.py` — за проверку,
обработку и хранение фотографии. Возвращение фокуса в окно после выбора файла
теперь проверяет сессию без пересоздания формы.
