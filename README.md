# NutriDay frontend

Весь React/JavaScript-фронтенд веб-версии Caloriesss v0.0.5 Mobile: дневник, продукты, порции, активности, авторизация, профиль и сканер. Это полная текущая версия интерфейса, включая функции, добавленные ранее. Исторические снимки каждого коммита здесь не собраны.

## Запуск

Нужен Node.js 22.12+ (или совместимая более новая версия).

```bash
cd frontend
npm ci
npm run dev
```

Открой адрес из терминала. Обычно это http://localhost:5173. Если порт занят, Vite выберет следующий. Приложению нужен отдельно работающий бэкенд Caloriesss v0.0.5 Mobile на http://127.0.0.1:8000. Python-кода и базы данных в этом архиве нет. Без API интерфейс покажет сообщение об отсутствии связи с сервером.

Если API запущен по другому адресу, скопируй .env.example в .env, измени API_PROXY_TARGET и перезапусти Vite. Это адрес для сервера Vite, не секрет и не пароль. Предпочтительно использовать локальный HTTP-бэкенд для разработки: Secure-cookie production-сервера не стоит проверять через обычный HTTP localhost.

Браузер обращается к /api на том же адресе, что и сайт. Vite перенаправляет эти запросы на Python. Не заменяй вызовы api() абсолютными адресами без отдельной настройки cookie/CORS. Если сервер отклоняет Origin, в его ALLOWED_ORIGINS должен быть точный адрес сайта. Стандартный мобильный бэкенд разрешает localhost и 127.0.0.1 на портах 5173–5199, 8000 и 8080. Для preview на 4173 добавь этот адрес в разрешённые на стороне бэкенда.

## Сборка

```bash
npm run build
npm run preview
```

Готовые статические файлы появляются в dist. preview — только проверка сборки на компьютере, не production-хостинг. На сервере сайт и /api должны обслуживаться через один HTTPS-домен: /api направляется на FastAPI, остальные пути — на dist. Vite proxy в готовую сборку не переносится.

## Камера и PWA

Камера требует разрешения браузера и защищённого контекста: HTTPS или поддерживаемый браузером localhost. IP компьютера по обычному HTTP на телефоне не подходит. Service Worker регистрируется только в production-сборке. Он сохраняет лишь страницу без сети и иконки, не дневник, фото и ответы API. Для добавления на экран iPhone нужен работающий адрес сайта.

## Файлы

App.jsx — запуск React, дневник, продукты, порции и активности.
Auth.jsx — регистрация, вход, проверка сессии и выход.
Profile.jsx — имя, фото, анкета; экспорт Avatar.
Barcode.jsx — камера, поиск штрихкода и импорт карточки.
client.js — общий fetch-клиент.
dailyGoal.js — отображение прогресса к дневной цели.
style.css — все стили и адаптивная вёрстка.
index.html — HTML-вход и метаданные.
vite.config.js — dev/preview proxy и порты.
public — manifest, offline.html, sw.js и иконки.
package.json — команды и зависимости; package-lock.json — точные версии.

В исходном полном проекте dev.mjs запускал и Python, и Vite. В отдельную папку он не включён, npm run dev запускает только Vite. В vite.config.js добавлены настройка адреса API через окружение и proxy для preview. Пользовательские компоненты, стили и PWA-файлы перенесены без изменения логики. Node_modules и dist не включены: они создаются установкой и сборкой.

Подробный учебный разбор каждого файла, функций и обработчиков поставляется отдельным документом. Исходный код сторонних библиотек в разбор не входит.
